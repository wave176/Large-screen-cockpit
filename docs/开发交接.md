# 开发交接指南

本文面向接手本仓库的同事：读完应能独立跑通、改组件、改存储与扩展能力。更细的选型论证见 [技术选型.md](./技术选型.md)。

## 1. 产品在做什么

一套**大屏可视化设计器 + 运行时**：

| 页面 | 路由 | 职责 |
|------|------|------|
| 首页 | `/` | 入口导航 |
| 设计器 | `/editor` | 拖拽布局、组件库、图层、属性、保存 |
| 运行时 | `/runtime` | 按 Schema 全屏适配渲染（给大屏展示用） |

数据模型是整份 **`ScreenSchema` JSON**（画布 + 分组 + 组件列表），不是按组件拆表。

## 2. 本地运行

```bash
npm install
npm run dev      # 开发（含 JSON 模拟后端）
npm run build    # vue-tsc + vite build
```

开发态持久化文件：`data/screens/screen-demo.json`。  
**注意**：模拟 API 只在 `vite` 中间件里生效，`preview` / 纯静态部署不会写盘。

## 3. 核心数据流

```
组件库点击 addComponent
        ↓
Pinia screen store（schema / selectedIds / persist）
        ↓
┌───────────────────┬────────────────────────┐
│ EditorCanvas      │ PropertyPanel / 图层   │
│ Moveable 改 layout│ 改 props / layout 字段 │
└─────────┬─────────┴────────────┬───────────┘
          ↓                      ↓
     防抖 persist() → PUT /api/screens/:id
          ↓
   data/screens/{id}.json
          ↓
Runtime：hydrate → ScreenCanvas + ComponentWrapper → registry 取组件视图
```

关键文件：

- `src/shared/types/schema.ts` — Schema 类型（改结构先改这里）
- `src/store/screen.ts` — 唯一业务状态中心
- `src/components/registry.ts` — 组件注册表（新增组件必改）
- `src/api/screen.ts` + `vite/mock-screen-api.ts` — 存取

## 4. 如何新增一个大屏组件

1. 在 `src/components/<分类>/Xxx.vue` 写视图，`defineProps<{ component: ScreenComponent }>()`。
2. 在 `registry.ts`：
   - `componentViews[type] = Xxx`
   - `componentMetas` 增加条目（label / category / defaultLayout / defaultProps）
   - 如需演示数据，在 `getDefaultDataSource` 补分支
3. 在 `propSchemas.ts` 登记「组件配置」Tab 字段（文字、颜色、图表数据等），否则属性面板只显示通用 props。
4. 静态数据约定放在 `component.dataSource.data`，用 `shared/utils/chartData.ts` 读取。
5. 图表类优先包一层 `charts/ChartHost.vue`（尺寸 + 主题底 + resize）。

同 `type` 可挂多个面板条目（如柱状/堆叠/横向），用 **label** 区分默认 props；创建时调用 `addComponent(type, label)`。

## 4.1 属性面板结构

右侧固定栏（与左侧对称），三个 Tab：

| Tab | 内容 |
|-----|------|
| 基础配置 | 名称、类型、分组、锁定/可见、X/Y/宽/高/层级 |
| 组件配置 | `propSchemas.ts` 专属表单（样式、标题等） |
| 数据源 | static / HTTP / SQL / WebSocket + 数据处理脚本（见 [开发交接 §4.3](./docs/开发交接.md#43-数据处理脚本怎么写)） |

聚焦属性输入时会隐藏画布选中框（`selectionChromeVisible`）。

## 4.2 动态数据源

组件通过 `useComponentData` 拉数（图表、列表等已接入）：

| type | 行为 |
|------|------|
| `static`（数据样例） | 使用 `dataSource.data`，可配 `transformScript` |
| `http` | 请求 `url`，可选轮询、`dataPath`、`mapping`，再经脚本 |
| `sql` | `POST /api/data/sql`（浏览器不直连库） |
| `websocket` | 订阅 `url`，推送经 `dataPath` / `mapping` / 脚本 |

**数据处理脚本**（`dataSource.transformScript`）：见下文 **§4.3**。

处理顺序：`拉取 → dataPath → mapping → transformScript → 组件渲染`

关键代码：`useComponentData.ts`、`resolveData.ts`、`runTransformScript.ts`。

## 4.3 数据处理脚本怎么写

脚本保存在 `dataSource.transformScript`。运行时等价于：

```js
const fn = new Function('raw', 'component', transformScript)
const result = fn(raw, component)  // result 即组件最终使用的数据
```

因此你写的是 **函数体（function body）**，不是单独再包一层 `function(raw) { ... }` 文件。  
在函数体内可以直接使用两个参数：

| 参数 | 含义 |
|------|------|
| `raw` | 接口/SQL 返回经 `dataPath`、`mapping` 处理后的数据 |
| `component` | 当前组件快照 `{ type, props }`，可读标题、模式等 |

**必须 `return` 一个对象**（或数组），结构需符合组件类型（柱状图要 `categories`/`values`，饼图要 `items` 等）。  
留空脚本则直接使用 `raw`。

### 写法一：直接 return（推荐）

```javascript
return raw.data
```

### 写法二：多步处理

```javascript
if (raw.code !== 200) {
  return { categories: [], values: [] }
}
return raw.data
```

### 写法三：根据组件 props 分支

```javascript
const title = component.props.title
return {
  categories: raw.list.map((item) => item.name),
  values: raw.list.map((item) => item.count),
}
```

### 写法四：函数表达式（平台会自动调用）

以下写法也支持，内部会编译成 `return (你的函数)(raw, component)`：

```javascript
function(raw) {
  return raw.data
}
```

或箭头函数：

```javascript
(raw) => raw.data
```

### 写法五：具名函数

```javascript
function transform(payload) {
  return payload.data
}
return transform(raw)
```

### 常见错误

```javascript
// ❌ 不要这样写——匿名 function 声明在 Function 体内非法
function(raw) {
  return raw.data
}
// 若仍报错，请改用「写法一」：return raw.data
```

实际上「写法四」的 `function(raw){...}` 现已由 `compileTransformBody` 自动包装；**最稳妥仍是写法一**。

### 示例：你的 HTTP 接口

接口：`GET http://127.0.0.1:5000/user/list`

返回：

```json
{
  "code": 200,
  "data": {
    "categories": ["A", "B", "C", "D"],
    "values": [12, 20, 15, 28]
  },
  "msg": "成功"
}
```

**数据源配置：**

| 字段 | 值 |
|------|-----|
| 类型 | HTTP 接口 |
| URL | `http://127.0.0.1:5000/user/list` |
| dataPath | （留空，raw 为整段 JSON） |
| 脚本 | `return raw.data` |

**或者不用脚本**，只设 `dataPath` 为 `data`，脚本留空，效果相同。

若接口返回的是 **JSON 字符串**（双重编码），可先解析：

```javascript
const body = typeof raw === 'string' ? JSON.parse(raw) : raw
return body.data
```

### 示例：饼图 items

```javascript
return {
  items: raw.records.map((r) => ({
    name: r.label,
    value: Number(r.total),
  })),
}
```

### 示例：滚动表格 rows

```javascript
return {
  rows: raw.data.map((item, index) => ({
    rank: index + 1,
    name: item.region,
    value: item.score,
  })),
}
```

### 调试建议

1. 属性面板「数据源」→ **测试拉取**，看下方预览是否为期望结构。
2. 脚本报错时，优先改成最简单的 `return raw` 确认 raw 长什么样，再逐步加工。
3. 动态源失败时画布会回退到「数据样例」里的 `dataSource.data`。

## 5. 设计器重要约定

- **画布坐标**：绝对定位 `layout.x/y/width/height`，单位 px，相对固定分辨率（默认 1920×1080）。
- **编辑缩放**：外层 CSS `zoom`；Moveable 传入相同 `zoom`，否则选框与元素错位。
- **成组**：`groups[]` + `component.groupId`；点组成员会选整组并一起拖。
- **选中框**：`selectionChromeVisible`；聚焦右侧属性 input 会隐藏 Moveable，避免改坐标后框留在原地。属性面板仍绑定 `selectedComponent`。
- **锁定 / 隐藏**：`locked` 不可拖；`visible: false` 不显示且不接收事件。

## 6. 运行时缩放

`runtime/hooks/useScale.ts` + `shared/utils/calcScale.ts`：按 `canvas.scaleMode`（fit / fill / stretch / none）计算 `scaleX/scaleY`，用 CSS `transform: scale` 适配视口。

## 7. 替换真实后端

保持文档形状即可：

```ts
{ version: number, updatedAt: string, schema: ScreenSchema }
```

把 `src/api/screen.ts` 的 `fetch` 指到真实服务；可删除或关掉 `vite/mock-screen-api.ts`。库表建议整份 Schema 存 JSON/JSONB。

## 9. 已知边界 / 后续

- 属性面板 props 目前是通用文本框；布尔值编辑后可能变字符串（`getPropBoolean` 已兼容 `"true"/"false"`）。
- 地图 / 视频仍为占位，待接 Cesium、hls/WebRTC。
- SQL 数据源经后端代理；开发态为 Mock，生产需接真实查询服务与权限。
- WebSocket 需服务端推送与组件字段结构对齐的 JSON。

接手优先读：`schema.ts` → `screen.ts` → `registry.ts` → `EditorCanvas.vue`。
