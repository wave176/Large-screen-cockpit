# 开发交接指南

本文面向接手本仓库的同事：读完应能独立跑通、改组件、改存储与扩展能力。更细的选型论证见 [技术选型.md](./技术选型.md)。

## 1. 产品在做什么

一套**大屏可视化设计器 + 运行时**：

| 页面 | 路由 | 职责 |
|------|------|------|
| 首页 | `/` | 入口导航 |
| 设计器 | `/editor` | 拖拽布局、组件库、图层、属性、保存 |
| 运行时 | `/runtime` | 按 Schema 全屏适配渲染（给大屏展示用） |

数据模型是整份 **`ScreenSchema` JSON**（画布 + 分组 + 组件列表），不是按组件拆表。

## 2. 本地运行

```bash
npm install
npm run dev      # 开发（含 JSON 模拟后端）
npm run build    # vue-tsc + vite build
```

开发态持久化文件：`data/screens/screen-demo.json`。  
**注意**：模拟 API 只在 `vite` 中间件里生效，`preview` / 纯静态部署不会写盘。

## 3. 核心数据流

```
组件库点击 addComponent
        ↓
Pinia screen store（schema / selectedIds / persist）
        ↓
┌───────────────────┬────────────────────────┐
│ EditorCanvas      │ PropertyPanel / 图层   │
│ Moveable 改 layout│ 改 props / layout 字段 │
└─────────┬─────────┴────────────┬───────────┘
          ↓                      ↓
     防抖 persist() → PUT /api/screens/:id
          ↓
   data/screens/{id}.json
          ↓
Runtime：hydrate → ScreenCanvas + ComponentWrapper → registry 取组件视图
```

关键文件：

- `src/shared/types/schema.ts` — Schema 类型（改结构先改这里）
- `src/store/screen.ts` — 唯一业务状态中心
- `src/components/registry.ts` — 组件注册表（新增组件必改）
- `src/api/screen.ts` + `vite/mock-screen-api.ts` — 存取

## 4. 如何新增一个大屏组件

1. 在 `src/components/<分类>/Xxx.vue` 写视图，`defineProps<{ component: ScreenComponent }>()`。
2. 在 `registry.ts`：
   - `componentViews[type] = Xxx`
   - `componentMetas` 增加条目（label / category / defaultLayout / defaultProps）
   - 如需演示数据，在 `getDefaultDataSource` 补分支
3. 静态数据约定放在 `component.dataSource.data`，用 `shared/utils/chartData.ts` 读取。
4. 图表类优先包一层 `charts/ChartHost.vue`（尺寸 + 主题底 + resize）。

同 `type` 可挂多个面板条目（如柱状/堆叠/横向），用 **label** 区分默认 props；创建时调用 `addComponent(type, label)`。

## 5. 设计器重要约定

- **画布坐标**：绝对定位 `layout.x/y/width/height`，单位 px，相对固定分辨率（默认 1920×1080）。
- **编辑缩放**：外层 CSS `zoom`；Moveable 传入相同 `zoom`，否则选框与元素错位。
- **成组**：`groups[]` + `component.groupId`；点组成员会选整组并一起拖。
- **选中框**：`selectionChromeVisible`；聚焦右侧属性 input 会隐藏 Moveable，避免改坐标后框留在原地。属性面板仍绑定 `selectedComponent`。
- **锁定 / 隐藏**：`locked` 不可拖；`visible: false` 不显示且不接收事件。

## 6. 运行时缩放

`runtime/hooks/useScale.ts` + `shared/utils/calcScale.ts`：按 `canvas.scaleMode`（fit / fill / stretch / none）计算 `scaleX/scaleY`，用 CSS `transform: scale` 适配视口。

## 7. 替换真实后端

保持文档形状即可：

```ts
{ version: number, updatedAt: string, schema: ScreenSchema }
```

把 `src/api/screen.ts` 的 `fetch` 指到真实服务；可删除或关掉 `vite/mock-screen-api.ts`。库表建议整份 Schema 存 JSON/JSONB。

## 8. 目录速查

| 路径 | 说明 |
|------|------|
| `src/editor/` | 设计器画布与侧栏 |
| `src/runtime/` | 运行时画布与包装器 |
| `src/components/` | 可投放组件实现 + registry |
| `src/shared/` | 类型、默认 Schema、工具 |
| `src/store/` | Pinia |
| `src/api/` | HTTP 客户端 |
| `vite/` | 开发态模拟后端 |
| `data/screens/` | JSON 文档落盘 |

## 9. 已知边界 / 后续

- 属性面板 props 目前是通用文本框；布尔值编辑后可能变字符串（`getPropBoolean` 已兼容 `"true"/"false"`）。
- 地图 / 视频仍为占位，待接 Cesium、hls/WebRTC。
- 数据源仅静态演示完善；`http` / `websocket` 类型已预留，未做运行时拉取。

接手优先读：`schema.ts` → `screen.ts` → `registry.ts` → `EditorCanvas.vue`。
