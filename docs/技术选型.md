# 大屏可视化项目 — 技术选型文档

> 文档版本：v2.1  
> 更新日期：2026-08-20  
> 目标：搭建支持**固定分辨率画布**、**组件化拖拽**、**数据源可配置**的可视化大屏平台；扩展支持 **3D 地图 + 视频 + 实时设备**（海康 IoT 路线）。配置以 **Schema JSON** 持久化（当前用本地 JSON 文件模拟后端）。技术栈全部采用**免费开源**方案。
>
> **代码接手 / 如何加组件 / 数据流**：见同目录 [开发交接.md](./开发交接.md)。

## 1. 项目需求概述

| 需求 | 说明 |
|------|------|
| 固定分辨率画布 | 支持 1920×1080、4K 等预设分辨率，组件按像素精确定位 |
| 可视化大屏 | 深色主题、装饰边框、动效；Runtime 等比缩放适配不同显示器 |
| 组件化拖拽 | 从组件面板拖入画布，支持移动、缩放、对齐、层级、撤销/重做 |
| 数据源配置 | 组件可绑定静态 JSON、HTTP API、WebSocket 等，支持字段映射与刷新策略 |
| 3D / 视频 / IoT（扩展） | 3D 地图（Cesium）、监控视频（HLS/WebRTC）、设备实时状态（WebSocket） |
| 零/低代码 | 非开发人员通过配置面板完成布局与数据绑定 |
| 成本约束 | 框架、图表库、拖拽库、构建工具均使用 MIT / Apache 2.0 等免费开源许可 |

## 2. 总体架构

### 2.1 平台分层

```
┌─────────────────────────────────────────────────────────────────┐
│                        大屏设计器（Editor）                       │
│  组件面板 │ 固定分辨率画布（Moveable） │ 属性面板 │ 数据源 │ 预览  │
└──────────────────────────────┬──────────────────────────────────┘
                               │ 保存 JSON Schema（canvas + 组件 + 数据源）
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│                        大屏运行时（Runtime）                      │
│  解析 Schema → scale 适配屏幕 → 动态注册组件 → 拉取/订阅数据       │
└──────────────────────────────┬──────────────────────────────────┘
                               │
         ┌─────────────────────┼─────────────────────┐
         ▼                     ▼                     ▼
   ECharts（2D 图表）    Cesium（3D 地图）    Video + WebSocket
   侧边面板 / 浮层        空间主舞台           监控 + 设备实时
         │                     │                     │
         └─────────────────────┴─────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│                     数据层（可选后端）                            │
│  REST API │ WebSocket │ 流媒体网关（RTSP→HLS/WebRTC）│ 数据库      │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **Editor / Runtime 分离** | 设计器负责编辑导出，运行时只读 Schema 渲染，便于部署到展示屏 |
| **Schema 驱动** | 画布分辨率、组件 layout、样式、数据源均以 JSON 描述 |
| **固定逻辑分辨率** | Schema 存设计稿像素坐标；显示时用 `transform: scale` 适配，不改 layout |
| **渲染职责分离** | ECharts 只做 2D 统计；Cesium 管 3D 空间；视频/设备各走专用通道 |
| **组件注册表** | 每类组件暴露统一的 `layout`、`props`、`dataSource`、`events` 接口 |

## 3. 画布技术选型（核心）

> 大屏画布采用**设计稿式绝对定位**，与 GoView、DataV、FineVis 一致；**不使用**栅格布局（vue-grid-layout）。

### 3.1 布局模型

| 项目 | 选型 | 说明 |
|------|------|------|
| 容器 | 原生 `div` | 不用 HTML `<canvas>`（ECharts/视频/Cesium 需 DOM） |
| 定位 | `position: absolute` | 每个组件按 x/y/width/height 像素定位 |
| 尺寸 | Schema 固定 `canvas.width / height` | 逻辑分辨率，不随屏幕变化 |
| 层级 | `z-index` + 图层树 | 支持置顶/置底 |
| 旋转 | `transform: rotate()` | 可选，Moveable 支持 |

### 3.2 固定分辨率预设

| 名称 | 分辨率 | 场景 |
|------|--------|------|
| 标准 FHD（默认） | **1920 × 1080** | 最常见指挥大屏 |
| 2K | 2560 × 1440 | 高分显示 |
| 4K | **3840 × 2160** | 展厅、指挥大厅 |
| 超宽 | 3840 × 1080 | 弧形屏、三联屏 |
| 竖屏 | 1080 × 1920 | 竖向广告屏 |
| 自定义 | 用户输入 W × H | 特殊 LED 屏 |

### 3.3 Editor 与 Runtime 结构

```
Editor（设计器）
├── 工具栏：分辨率选择 │ Editor 预览缩放 50%/75%/100%
├── viewport（可滚动、居中）
│   └── transform: scale(editorPreviewScale)   ← 仅方便编辑，不写进 Schema
│       └── canvas（固定 canvas.width × canvas.height）
│           ├── ComponentWrapper × N（absolute）
│           └── Moveable（挂当前选中组件）
└── 属性面板 / 图层树 / 数据源配置

Runtime（运行时）
├── screen-wrapper（100vw × 100vh，居中）
│   └── transform: scale(calcScale)              ← 根据屏幕与 scaleMode 计算
│       └── canvas（与 Editor 相同固定尺寸）
│           └── ComponentWrapper × N（只读，无 Moveable）
└── resize 监听 → 重算 scale + chart.resize() / viewer.resize()
```

### 3.4 屏幕适配模式（scaleMode）

| 模式 | 算法 | 适用 |
|------|------|------|
| **fit**（默认） | `scale = min(vw/W, vh/H)`，等比适应，可能留黑边 | 不变形，行业默认 |
| **fill** | `scale = max(vw/W, vh/H)`，等比铺满，可能裁切 | 不允许黑边 |
| **stretch** | 宽高分别缩放 | 一般不用，会变形 |
| **none** | scale = 1 | 物理屏即设计分辨率 |

```typescript
function calcScale(
  canvasW: number,
  canvasH: number,
  mode: 'fit' | 'fill' | 'stretch' = 'fit'
) {
  const vw = window.innerWidth
  const vh = window.innerHeight
  const scaleX = vw / canvasW
  const scaleY = vh / canvasH
  if (mode === 'stretch') return { scaleX, scaleY }
  if (mode === 'fill') {
    const s = Math.max(scaleX, scaleY)
    return { scaleX: s, scaleY: s }
  }
  const s = Math.min(scaleX, scaleY)
  return { scaleX: s, scaleY: s }
}
```

### 3.5 画布交互选型

| 类别 | 选型 | 许可证 | 用途 |
|------|------|--------|------|
| 拖拽 / 缩放 / 旋转 | **Moveable**（`@daybrush/moveable`） | MIT | Editor 内改变 layout |
| 对齐 / 吸附 | **Moveable Snappable** | MIT | 组件边缘对齐、参考线 |
| 多选 / 框选 | **Selecto**（`@daybrush/selecto`，可选） | MIT | 批量选中与操作 |
| 组件面板拖入 | **VueDraggable**（Sortable.js） | MIT | 从左侧面板拖入画布 |
| 标尺 | **vue3-sketch-ruler**（可选） | MIT | 设计器标尺体验 |
| 撤销 / 重做 | Pinia + History 栈（自研） | — | 操作回退 |
| 画布状态 | **Pinia** | MIT | 分辨率、选中态、组件树 |

**拖入坐标反算**：Editor 有预览缩放时，drop 坐标需除以 `editorPreviewScale` 再写入 Schema。

### 3.6 不采用的方案

| 方案 | 原因 |
|------|------|
| vue-grid-layout | 栅格 12 列，无法 1920×1080 像素级布局 |
| Flex / Grid 流式 | 组件尺寸不可控，不符合设计稿 |
| HTML `<canvas>` 画板 | 无法嵌 ECharts / 视频 / Cesium |
| rem / vw 流式 | 适合 H5，不适合固定设计稿 + 整体 scale |

## 5. 可视化分层选型（海康 IoT 路线）

> **原则**：3D 地图管空间，ECharts 管 2D 统计，视频与设备实时各走专用协议，职责不混用。

### 5.1 分层职责

```
canvas 1920×1080
├── Map3D（Cesium）     ← 园区/城市 3D、设备点位、围栏、轨迹
├── Chart*（ECharts）   ← 侧边/底部 KPI、饼图、折线、排名（2D 面板）
├── VideoPanel          ← 监控多分屏（HLS / WebRTC）
├── DeviceLayer         ← WebSocket 驱动的 Cesium Entity 点位
└── Decoration*         ← SVG/CSS 边框、标题、装饰
```

### 5.2 2D 图表层 — ECharts

| 类别 | 选型 | 说明 |
|------|------|------|
| 图表库 | **Apache ECharts** | 柱状/折线/饼图/排名/小型 2D 地图 |
| Vue 集成 | **vue-echarts** | 按需引入 `echarts/core` |
| 位置 | 独立 DOM 面板 | **不用** ECharts GL / map3D 做主 3D |
| 实时 | 增量 `setOption`，`animation: false` | 滑动窗口保留最近 N 点 |
| resize | 容器变化时 `chart.resize()` | scale 后必须调用 |

### 5.3 3D 地图层 — Cesium

| 类别 | 选型 | 说明 |
|------|------|------|
| 主引擎 | **CesiumJS** | 数字孪生园区/城市、3D Tiles、GIS |
| Vue 集成 | **vue-cesium** 或 `@cesium/engine` 直封 | 与固定 layout 容器配合 |
| 3D 补充 | **Three.js**（按需） | 精细 glTF 动画、Cesium 内嵌场景 |
| 2D 地图备选 | **MapLibre GL JS** | 轻量 2D GIS，无精细 3D 时 |
| 数据 | 3D Tiles、GeoJSON、glTF | 建筑、围栏、设备模型 |
| 底图 | 天地图等合法源 | **国内需审图号合规** |

**引擎对比（本项目）**：

| 引擎 | 角色 |
|------|------|
| **Cesium** ✅ 主选 | 3D 地图、数字孪生、设备空间点位 |
| Three.js | Cesium 补充，复杂模型/特效 |
| MapLibre | 仅 2D 矢量地图的轻量场景 |
| Mapbox GL | 商业授权成本高，非首选 |

### 5.4 视频层

| 方案 | 场景 | 库 |
|------|------|-----|
| **HLS** | 回放、延迟 3～10s 可接受 | **hls.js** |
| **WebRTC** | 实时监控、低延迟 | 原生 RTCPeerConnection 或 SRS/mediamtx 网关 |
| 摄像头接入 | 浏览器不支持 RTSP | 后端 **FFmpeg / SRS** 转 HLS 或 WebRTC |

视频组件独立 `<VideoPanel>`，不塞进 Cesium 纹理（除非监控墙贴图等特殊场景）。

### 5.5 实时设备层

| 类别 | 选型 | 说明 |
|------|------|------|
| 协议 | **WebSocket** / MQTT over WS | 设备状态、告警、传感器 |
| 地图联动 | Cesium Entity / Billboard | 批量更新点位与状态色 |
| 图表联动 | ECharts 时序 | 消息缓冲 + 批量更新，避免每帧 setState |
| 列表 | 虚拟滚动 | 大量设备/告警列表 |

### 5.6 装饰组件

| 类别 | 选型 |
|------|------|
| 边框 / 装饰 | 自研 SVG/CSS，参考 GoView、DataV-Team/DataV |
| 动效 | CSS Animation 为主；GSAP 商业项目注意许可 |

### 7.7 扩展新组件流程

1. 在 `registry.ts` 注册 `type`、默认 `layout` 与 `props`
2. 实现 `XxxView.vue`（Runtime 视图）+ `XxxConfig.vue`（Editor 属性表单）
3. 若有数据绑定，实现 `transformData(raw, mapping)`
4. 在 Editor 组件面板添加入口

### 9.2 Schema 持久化方案（推荐）

大屏配置是 **文档型数据**，前后端统一存储整份 `ScreenSchema` JSON，不要一开始拆成「每个组件一行」。

#### 文档结构（落库 / 落文件）

```json
{
  "version": 1,
  "updatedAt": "2026-08-20T13:14:22.525Z",
  "schema": {
    "id": "screen-demo",
    "name": "智慧园区大屏",
    "canvas": { "width": 1920, "height": 1080, "scaleMode": "fit", "...": "..." },
    "groups": [],
    "components": []
  }
}
```

| 字段 | 说明 |
|------|------|
| `version` | 文档版本，每次保存 +1，便于后续乐观锁 |
| `updatedAt` | 最近保存时间 |
| `schema` | 前端 Pinia 中的完整 `ScreenSchema`（画布 + 分组 + 组件布局/属性/数据源） |

#### 正式后端表设计（后续）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键 |
| `name` | varchar | 大屏名称 |
| `schema_json` | JSONB / JSON | 整份 Schema 或整份 Document |
| `version` | int | 版本号 |
| `status` | varchar | draft / published |
| `updated_at` | timestamp | 更新时间 |

可选再加 **发布快照表**，Runtime 读已发布副本，Editor 改草稿互不影响。

#### API 约定

```
GET    /api/screens           # 列表
GET    /api/screens/:id       # 读取文档
PUT    /api/screens/:id       # 保存 { schema, version }
POST   /api/screens           # 新建
```

### 9.3 当前阶段：JSON 文件模拟后端（已实现）

开发期不接真实数据库，用 **Vite 中间件 + 本地 JSON 文件** 模拟后端读写：

```
data/screens/
└── screen-demo.json     ← 整份 ScreenDocument
```

| 能力 | 实现 |
|------|------|
| 读 | `GET /api/screens/:id` → 读 `data/screens/{id}.json` |
| 写 | `PUT /api/screens/:id` → 覆盖写入该 JSON，`version++` |
| 列表 | `GET /api/screens` → 扫描 `data/screens/*.json` |
| 前端 | `src/api/screen.ts` + Pinia `hydrate()` / 防抖 `persist()` |
| 中间件 | `vite/mock-screen-api.ts`（仅 `npm run dev` 生效） |

**行为：**
- 进入设计器 / Runtime 时从 JSON 文件加载
- 拖拽、改属性后 **600ms 防抖自动保存** 到文件
- 工具栏可手动「保存到 JSON」，并显示版本与状态

**替换真实后端时：** 仅需把 `src/api/screen.ts` 的 `fetch` 地址改成真实服务，Schema 结构不变。

### 9.4 后端技术选型（正式环境）

| 类别 | 选型 | 说明 |
|------|------|------|
| API | Node.js + **Fastify** / **NestJS** | 项目管理、Schema 存储 |
| 或 | **Spring Boot** | 企业 Java 栈 |
| 数据库 | PostgreSQL（JSONB）/ MySQL（JSON） | 存 `schema_json` |
| 对象存储 | MinIO / OSS | 背景图、缩略图 URL |
| 流媒体 | **SRS** / FFmpeg | RTSP → HLS / WebRTC |
| 缓存 | Redis（可选） | 会话、API 缓存 |

> 图片不要塞进 JSON，上传后 Schema 只存 URL。

## 14. 风险与注意事项

1. **地图合规**：国内底图需审图号；Cesium 接天地图等合法源。  
2. **scale 与 resize**：Runtime scale 变化后，ECharts 需 `chart.resize()`，Cesium 需 `viewer.resize()`。  
3. **Editor 坐标**：拖入/拖拽需区分 Editor 预览 scale 与设计坐标。  
4. **性能**：Cesium + 多路视频 + 多 ECharts 同屏 GPU/内存压力大；限制视频路数、ECharts 关动画。  
5. **视频协议**：浏览器不支持 RTSP，必须经流媒体网关转 HLS/WebRTC。  
6. **ECharts 体积**：按需引入，避免全量打包。  
7. **Cesium 体积**：静态资源分包或 CDN，按需加载。  
8. **WebSocket 海量设备**：消息缓冲 + 批量更新，地图 Entity 合并策略。  
9. **浏览器**：面向 Chrome / Edge 最新版；不对 IE 兼容。

## 15. 总结

本项目采用 **Vue 3 + TypeScript + Vite + Pinia** 为基础，画布使用 **固定分辨率 + absolute 布局 + Moveable 编辑 + CSS scale 运行时适配**，可视化按职责分为：

- **ECharts** — 2D 统计图表（面板/浮层）
- **Cesium** — 3D 地图与空间设备（主舞台）
- **hls.js / WebRTC** — 监控视频
- **WebSocket** — 实时设备与告警

通过 **Schema 驱动** 的 Editor / Runtime 分离架构，实现可拖拽、可配置数据源的大屏平台。配置数据以 **整份 JSON 文档** 持久化：当前阶段写入 `data/screens/*.json` 模拟后端；正式环境替换为数据库 JSON 字段即可，前端 Schema 契约保持不变。
